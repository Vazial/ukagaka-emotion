# eli5 — 前提知識ゼロで読める言葉に直す

## これは何か

直前の説明を、このリポジトリを一度も見たことがない人に通じる言葉で言い直す。

これは**救済**であって予防ではない（`meta/adr/0060` 決定5）。呼ばれた時点で、会話を短く保つ
規程（`meta/permissions.md` §2 提示の仕方）をすり抜けている。言い直したあと、**なぜ最初から
そう書けなかったか**を1行で振り返る。

## 何を対象にするか

引数が無ければ**直前の自分の発言**。引数があればそれを対象にする。

- `/eli5` — 直前の説明を言い直す
- `/eli5 <ファイルパス>` — そのファイル（PR本文・ADR・規程など）を言い直す
- `/eli5 <貼られた文章>` — その文章を言い直す

## 手順

### 1. 相手が何を知らないかを決める

既定の想定読者は「このリポジトリを見たことがない、ソフトウェア開発の一般用語は分かる人」。
`/eli5` を呼んだのが人間なら、その人が**直前に何につまずいたか**を優先して埋める。

### 2. 捨てる

言い直し文からは次を消す。残すのは、消すと意味が変わるものだけ。

- ADR番号・FR番号・信条の番号（`P-04` など）・シナリオID
- ファイルパス・関数名・コマンド名
- このリポジトリでしか通じない語（施錠・走破・スライス・ゲート・断面・cause_key・A層/B層/C層 など）
- 数字の羅列（件数・割合・SHA）。判断を変えない数字は落とす

固有の名前をどうしても残すなら、**何の話かを先に書き、名前を後ろに括弧で置く**。
「番号のつけ方を決めた回（ADR-0052）」の順にする。逆順にしない。

### 3. 組み立てる

次の順で書く。全体で**15行以内**を上限とする。

1. **一言で何の話か**（1行）
2. **何が困っているのか**（2〜3行）。誰が、何をしようとして、何ができなかったか
3. **どうしたいのか / どうなるのか**（2〜4行）
4. **あなたに何をしてほしいか**（あれば。1〜2行）。無ければ「今のところ何もしなくていい」と書く

判断を仰ぐなら、ここで文章にせず選択ボタンで出す（`meta/permissions.md` §2 提示の仕方 2）。

### 4. 文の作り方

- 1文は40字を目安に。長くても60字で切る
- 1段落は3文まで
- 比喩は1つまで。2つ以上使うと、比喩どうしが噛み合わずかえって分かりにくくなる
- 「つまり」「要するに」で始めた文が元の文より長いなら、書き直す
- 断定して書く。「〜と思われる」「〜の可能性がある」で濁さない。確かでないなら「ここは確認して
  いない」と別の行に書く

### 5. 振り返る（1行）

言い直しの最後に、次の形で1行だけ添える。

> 最初からこう書けなかった理由: <調べた直後で全部知っている気になっていた / 作業量を見せたかった / 判断に要らない証跡を混ぜた / その他>

この1行は自己批判のためではない。同じ原因が続くなら、`meta/adr/0060` 決定6の後退条件
（会話ではなく道具の側で縛る）へ進む材料になる。

## やらないこと

- **内容を変えない**。分かりやすくするために結論をぼかしたり、都合の悪い部分を落としたりしない。
  難しいまま伝えるべき制約があるなら、難しいと書いたうえで一番大事な1つだけ残す
- **短くしただけで終わりにしない**。短くても専門用語が残っていれば失敗である
- **子供扱いしない**。平易な言葉で書くことと、内容を薄めることは違う
