# ADR-0072: チャットで既に合意した内容を公表するだけのPRは、AIがマージまで行ってよい

> **承認者向けサマリ**
>
> 2026-09-27、テンプレ取り込みの登録漏れ対策（ADR-0069〜0071）で、チャットでの合意自体は速かったが、
> 合意後に「PRを出す→人間がマージするまで次に進めない」という直列実行が進行を遅くしていた。
> 調べると、mainのbranch protectionはレビュー0件（`required_approving_review_count: 0`）で、
> 「人間だけがマージできる」はGitHubの技術的な制限ではなく`meta/guardrails.md`の運用ルールだった。
>
> 決定は1点。**次の3種類に限り**、AIはPRの作成からマージまでを自分で行ってよい。
>
> 1. ADRの`status`/`approved_by`を、チャットで得た合意のとおりに`承認済み`へ確定するだけの記録
> 2. `meta/derived-repos.md`のような表への、既に合意した1行の追加
> 3. typo・整形など、意味を変えない修正
>
> これ以外（契約・設計骨格・step実装・信条規程の新しい制約）は、これまでどおり人間がマージする。
>
> 払うもの: 上の3種類に該当するかの判定をAI自身が行う。判定を誤ればgovlintの検査（下記）で止まる。

## 文脈

`meta/permissions.md`は「記録のADR」（すでに決まったことを書き留めるもの）を**AIが自律更新可（承認不要）**としている（meta/adr/0061）。
一方`meta/guardrails.md`は、mainへのマージを**人間のみができること**と定める（meta/adr/0064 決定4）。
この2つの間に、今回すり抜けなかった隙間があった。**「制約のADR」（ADR-0069〜0071のように、次にAIが何をしてよいかを変える決定）の
本体そのものは、これまでどおり合意が要る**。だが、合意が済んだあとに`status`を`提案中`から`承認済み`へ確定するだけの
コミット（例: PR #216）は、それ自体は新しい制約を何も持ち込んでいない。それでも同じマージの壁に当たり、
1本のPR＋人間のマージ待ちを要求した。

branch protection（ruleset `protect main`）を実際に見ると、必須レビューは0件で、必須ステータスチェックは
L0（govlint）のみだった。「人間だけがマージ」はGitHubではなく`meta/guardrails.md`が課している運用ルールである。

## 決定

次の3種類に限り、AIはPRの作成・L0の確認・マージまでを自分で行ってよい。いずれも**新しい制約を持ち込まない**ことが条件。

1. **承認記録**: ADRの`status`を`提案中`から`承認済み`へ、`approved_by`をチャットで得た合意のとおりに確定するコミット。
   このコミットの中に、ADR本文・orchestration.md等への実質的な変更を混ぜない
2. **表への1行追加**: `meta/derived-repos.md`のような一覧表へ、既にチャットで合意した1行を足すだけのコミット
3. **typo・整形**: 意味を変えない誤字修正・空白・見出しの整形

これ以外——契約・設計骨格・step実装・信条規程そのものの新しい制約を持ち込むADR・PRINCIPLES/permissions/guardrails/
`.claude/agents/**`/HANDOFF.mdの変更——は、`meta/adr/0064`のとおり人間がマージする。

govlintに、上の3種類に該当すると自称しながら実際は他ファイルを変えているPRを検出する検査を足す
（コミットメッセージの型と変更ファイルの対応。ERROR）。**この検査はdeveloper役で別途実装する**。

## 検討した代替案

- 全ての規程変更でAIにマージ権限を渡す / 不採用の理由: `meta/adr/0064`決定4の条件（各プロジェクトのL1〜L4必須化・adr-number.yml必須化）が揃っていない。新しい制約そのものの是非は、引き続き人間が最後に確かめる
- branch protectionを変更してAI用のbypass actorを設定する / 不採用の理由: 技術的な特例を増やすと、他の変更にも波及して境界が曖昧になる。判定はコミットの中身（3種類に該当するか）に置き、仕組みは今のPRフローのままにする
- 何もしない（都度承認を続ける） / 不採用の理由: 今回2026-09-27に「進行を阻害している」という指摘が出た。記録だけのコミットにまで人間のクリックを要求するのは、`meta/adr/0064`の「マージは承認ではなく公表」という原則そのものに反する

## 帰結

- ADR-0070・0071のような「記録の確定」PR（例: #216）は、今後この決定が承認されれば、AIがマージまで行える
- 契約・設計骨格・step実装・信条規程の新しい制約は、引き続き人間がマージする。委譲の範囲は広げていない
- 誤判定を検出する機械検査は、この決定の承認後に別タスクとして実装する
