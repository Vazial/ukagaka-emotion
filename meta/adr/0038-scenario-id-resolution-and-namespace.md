# ADR-0038: シナリオIDの参照境界をASCIIで定め、定義形式を厳格化し、名前空間をリポジトリ全体にする

> **承認者向けサマリ**: `meta/tools/govlint.py` のシナリオID検査（L0）に3つの欠陥が見つかった。
> **(1)** 参照の単語境界に `\b` を使っているため、Pythonの `\w` がUnicode文字を含む結果、**日本語の
> 助詞が直後に来る参照（`RSV-C-10が…`）が検出されない**。統治文書は日本語で書かれるので、これは
> 参照整合の検査に恒常的な穴を開けていた。**(2)** 行頭コメントがIDで始まれば「定義」と誤認するため、
> 説明のために行頭でIDに触れた散文（`# RSV-C-05〜C-07が終了時刻の…`）が**実在しない定義を生み**、
> 参照検査を骨抜きにしていた。**(3)** 検査が `projects/<p>/contracts` ディレクトリ単位で閉じている
> ため、ADR-0023（consumer-driven contract）とADR-0025（契約SSoT）が正当と認める**クロスプロジェクト
> 参照が原理的に解決できない**。実害は測定済みで、既存の `reservation-booking.feature` が緑なのは
> **偶然**だった——同じ内容を書いても「書いた位置」と「直後の1文字」で通るか落ちるかが変わる状態に
> あった。決定は3点: 参照の境界をASCIIで定める／定義はIDが行の主語（続くのが行末かコロン）のときだけ
> とする／**名前空間をリポジトリ全体で1つにする**。3点は互いに依存しており**同時に入れる必要がある**
> （片方だけ直すと既存文書が落ちる。下記「なぜ分割できないか」）。既存の定義36行は1件も壊れず、
> 検査は緩まず**強くなる**。ツールの修正のみで、契約ファイルの中身は変更しない。

## 文脈

### 1. 発覚の経緯

RFE-C（`projects/reservation-frontend/contracts/my-reservations.feature`）の契約ドラフトを
orchestratorが govlint にかけたところ ERROR 4件で落ちた（architectは機械検証を通さず「矛盾なし」と
報告していた。FR-018）。内訳は「`RFE-B-03` の定義が重複」1件と「`RSV-K-02`・`RSV-K-08`・`RSV-K-09`
が未定義」3件である。

差し戻して修正する過程で、**同じことをしている既存ファイルが通っている**ことに気づき、
`check_scenario_ids` の実装を読んで原因を測定した。

### 2. 測定した3つの欠陥

**欠陥(1): 参照の単語境界が言語依存**

```python
SCENARIO_ID_RE = re.compile(rf"\b({SCENARIO_ID})\b")
```

Pythonの `re` は str に対して `\w` をUnicode拡張で解釈するため、仮名・漢字は単語文字である。実測:

| 記述 | 参照として検出されるか |
|---|---|
| `RSV-C-10が定員超過` | **されない**（直後の `が` が `\w`） |
| `RSV-C-10は欠番` | **されない** |
| `RSV-C-10(定員)` | される |
| `RSV-C-10〜` | される |
| `RSV-C-10。` | される |

日本語の散文でIDに言及すると直後は助詞になるのが普通なので、**参照整合の検査は日常的に空振りしていた**。

**欠陥(2): 行頭コメントの誤認**

```python
DEFINE_COMMENT_RE = re.compile(rf"^\s*#\s*({SCENARIO_ID})\b", re.M)
```

「IDで始まる行頭コメント」を定義とみなす。しかし説明のために行頭でIDに触れた散文も一致する。実測された実害:

- `projects/reservation-frontend/contracts/reservation-booking.feature:55` の
  `#     RSV-C-05〜C-07が終了時刻の妥当性を…` が、**フロントのディレクトリで `RSV-C-05` を「定義」して
  いた**（直後が `〜` なので `\b` が成立した）。実在しない定義が、同ファイル58行目の `RSV-C-10` 参照と
  あわせて検査を骨抜きにしていた。
- `projects/reservation-system/contracts/reservation-rules.feature:22` の
  `#       RSV-R-02で明示的にロックした…` は同じ形だが、直後が `で` のため**偶然セーフ**だった。同ファイル
  53行目に本物の `RSV-R-02` 定義があるので、欠陥(1)だけを直すと**これが重複エラーになる**。

**欠陥(3): 名前空間がディレクトリ単位**

`for contracts in sorted((ROOT / "projects").glob("*/contracts")):` のループ内で `defined` を作るため、
フロントの契約がバックエンドのシナリオIDを引くと必ず未定義になる。ところが ADR-0023 は
consumer-driven contract（UIの設計がバックエンド契約の形を駆動してよい）を認め、ADR-0025 は契約のSSoTを
バックエンド側の1本に定めている。**フロントの契約がバックエンドのシナリオを導出根拠として引くのは正当**
であり、実際 `reservation-booking.feature` は control surface の導出根拠として
「終了時刻を自由度に入れるのは `RSV-C-05`〜`C-07` が終了時刻の妥当性を拒否理由に持つため」と書いている。
検査がこれを表現できないのは**ツール側の制約であって、書き方が間違っているのではない**。

### 3. なぜ分割できないか

3点は互いに依存する。片方だけ入れると既存文書が落ちる:

| 入れるもの | 起きること |
|---|---|
| (1)のみ | `RSV-R-02で…` が定義扱いのまま検出されるようになり、本物の定義と**重複エラー**。`RSV-C-11は欠番` も定義扱いになり「欠番なのに定義もされている」エラー |
| (1)+(2) | 偽定義は消えるが、`RSV-C-05`・`RSV-C-10` が**未解決参照として顕在化**（実測2件） |
| (1)+(2)+(3) | **ERROR 0**（実測。定義42件・衝突なし） |

したがって本ADRは3点を1つの決定として扱う。

## 決定

### 1. 参照の境界はASCIIで定める

```python
SCENARIO_ID_RE = re.compile(rf"(?<![A-Za-z0-9-])({SCENARIO_ID})(?![A-Za-z0-9-])")
```

シナリオIDはASCIIなので、境界条件は「IDの構成文字（英数字とハイフン）が前後に続いていないこと」で
定める。`\b`（Unicode語境界）に依存しない。これにより直後が仮名・漢字・記号のいずれでも等しく検出し、
かつ `RSV-A-011` のような別IDへの部分一致は防ぐ。

### 2. 定義はIDが行の主語のときだけ

```python
DEFINE_COMMENT_RE = re.compile(rf"^\s*#\s*({SCENARIO_ID})\s*(?::|$)", re.M)
```

IDに続くのは**行末かコロン**だけを認める。既存の統治文書が使う2形式（`# <ID>` と `# <ID>: 説明`）は
どちらも通り、**既存の定義36行は1件も壊れない**（全プロジェクトの定義行を列挙して実測確認済み）。
説明のために行頭でIDに触れた散文は定義扱いされなくなる。

### 3. 名前空間はリポジトリ全体で1つとする

`defined` / `retired` / `texts` の収集を全 `projects/*/contracts` にまたがって行い、参照はリポジトリ
全体の定義に対して解決する。採番プレフィックスはスライスごとに固有（RFE-A/B/C・RSV-A/C/K/L/R、
実測で衝突ゼロ）なので、衝突は起きない。

**重複検出も全体に効くようになる**——同じIDが別プロジェクトで定義されたらエラーになる。すなわち本決定は
検査を緩めるのではなく**強くする**。これは ADR-0023・ADR-0025 が既に認めている協調の形を、検査が
表現できるようにする変更である。

### 4. 適用範囲

ツール（`meta/tools/govlint.py`）とそのテストのみを変更する。**契約ファイルの中身は変更しない**。
RFE-C のドラフトで行った「クロスプロジェクトの採番済みIDを引かない」書き換え（PR #49）は、本ADR
以後は必須ではなくなるが、遡って書き戻すことはしない（内容は業務の言葉で自己完結しており、
書き戻す利益がない。P-05）。

## 検討した代替案

- **案A: 「フロントの契約に他プロジェクトの採番済みIDを引かない」を規約にする**（現状の運用回避） /
  不採用: ADR-0023・0025 が認める協調のトレーサビリティを、ツールの制約のために捨てることになる。
  control surface の導出根拠を番号で辿れなくなるのは実質的な損失であり、ADR-0024 が「導出規則からの
  誤導出」を事故として記録している経緯に照らしても、根拠の追跡可能性は下げるべきでない。
- **案B: 欠陥(1)のみ直す** / 不採用: 「なぜ分割できないか」の通り、既存文書が落ちる。
- **案C: 定義を明示マーカー（`# @scenario RSV-A-01` 等）にする** / 不採用: 既存の全 `.feature`
  36箇所の書き換えを要求する。決定2の形式なら既存文書が無変更で通るため、移行コストを払う理由がない。
- **案D: 参照検査そのものを弱める（未定義参照をREPORTに格下げ）** / 不採用: 参照整合はIDの誤記・
  消滅を機械が確定できる領域であり、P-04に照らしてERRORが正しい強制レベル。穴が空いていたことを
  理由に検査を諦めるのは逆方向。
- **案E（採用）: 3点を1つの決定として同時に入れる** / 採用: 既存文書を壊さず、検査を強くし、
  ADR-0023・0025 が認める協調を表現できるようにする最小の変更。

## 帰結

- 日本語の散文中のシナリオID参照が検査対象になる。**これまで空振りしていた検査が実際に効き始める**ため、
  今後の契約で誤記・消滅したIDへの参照が捕まる。
- 説明のために行頭でIDに触れても定義扱いされない。実在しない定義が生まれなくなる。
- フロントの契約がバックエンドのシナリオを導出根拠として引ける（ADR-0023・0025 の実装上の裏付け）。
- 重複検出がリポジトリ全体に効く。**同じIDを別プロジェクトで定義するとエラーになる**。採番の衝突を
  避ける責任が全体に及ぶ点は、新プロジェクト追加時に留意が要る（現状はプレフィックスがスライス固有
  なので実害なし）。
- 本ADRはツールとテストのみを変更する。契約ファイル・規程本体（`meta/verification.md` 等）の記述は
  変更しない——本ADRは既存の検査意図（「参照は実在の定義に解決する」「定義は一意」）を**正しく実装し直す**
  ものであり、検査の意図そのものを変えていない。
- 併せて friction-log に FR-018 を起票する（cause_key: `lint-rule-language-dependent`）。この摩擦は
  「機械検証を通さずに成果物を提出した」というagent側の見逃し（FR-018の直接の引き金）と、
  「lint規則が言語依存で偶然通っていた」という構造的欠陥の2層からなる。
