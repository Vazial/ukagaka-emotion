# ADR-0013: HANDOFF.mdは入口ポインタに徹し、揮発性状態も重複も持たない

## 文脈

4スライス + 規程改善バッチ3本を1つのセッションで走らせてきた。この間、フレッシュなセッションが文書だけで文脈を引き継げるか（コールドスタート経路）は一度も検証されていなかった。改めてHANDOFF.mdを読むと2つの問題があった。

1. **揮発性状態の陳腐化（P-11違反）**: 5節「次のタスク」の5項目（リポジトリ初期構成・guardrails実体作成・アーキテクチャ選定・最初のスライス・friction-log運用開始）はすべて完了済みで、フレッシュセッションはここを読むと終わった仕事を指示される。「次に何をするか」という現在状態を不変であるべき文書に置いたことが原因（P-11「現在はactiveContextだけが持つ」に反する）。

2. **重複の陳腐化（P-04違反）**: 揮発性状態を除いても、HANDOFFの大半は他の権威ある文書の再掲だった。agent体制→agents.md、思想→PRINCIPLES、運用ルール→PRINCIPLES/permissions、ファイル索引→meta/README。再掲は必ずドリフトする（実際、ファイル索引の「templates 6枚」は既に7枚、「guardrails実体は未作成」も完了済みで陳腐化していた）。5節と同じ病気のより広い版。

加えてHANDOFF.mdの更新権限がpermissions.mdの権限マトリクスに載っておらず、更新責任者が不在だった。

## 決定

1. **HANDOFF.mdは入口ポインタに徹する**。持つのは (a) 一段落の「これは何か」 (b) 読み始める順（activeContext → PRINCIPLES → agents.md → meta/README） (c) この文書自体の扱い、のみ。**中身は各文書が持ち、HANDOFFでは繰り返さない**。agent体制・思想・運用ルール・ファイル索引は、その権威ある出所へのポインタに置き換える
2. **揮発性の状態（進捗・次のタスク）を一切持たない**。「今どこにいて次に何をするか」はactiveContext.mdが唯一のSSOT（P-11）
3. **permissions.mdの権限マトリクスにHANDOFF.mdの行を追加する**: 不変のオンボーディング文書。変更はA層規程と同格でADR必須・人間承認

## 検討した代替案

- 案A: 5節のテキストだけ現状に合わせて更新する / 不採用: また陳腐化する。揮発性状態を静的文書に置く構造が原因で、テキスト修正は対症療法。かつ重複（P-04違反）が残る
- 案B: HANDOFF.mdを廃止しmeta/READMEかactiveContextに統合する / 不採用: 「フレッシュな読者はどこから読むか」という入口の指示は、どの既存文書も単独では担っていない小さな固有機能。かつ「HANDOFF読んで」はClaude Codeの慣習的な入口で、公開リポジトリの第一印象にもなる。薄く残す方が良い
- 案C: 不変オンボーディング（agent体制・運用ルール等を含む）として残す / 不採用: それらは他文書の再掲であり、5節と同じくドリフトする。入口ポインタまで削るのが正しい

## 帰結

- フレッシュセッションが「HANDOFF読んで進めて」で起動したとき、終わった仕事を指示されず、進行中のスライスに合流できる。コールドスタート経路が機能する
- HANDOFFがドリフトする面が構造的に無くなる（揮発性状態を持たず、内容を再掲しないため）
- HANDOFF.mdが権限マトリクスに載り、更新責任（ADR必須）が定まる
- クロスセッション経路の実地検証は別途行う（成果物の抽出と検証は結合させない。ルーティン化されたスライスをフレッシュセッションに拾わせる形が低リスク）
- FR-010として記録
