# ADR-0006: PRで提案するADRは、状態を「承認済み（本PRのマージをもって承認）」と書いてよい

## 文脈

規程改善バッチ（PR #2）で、ADRの状態を「提案中」でマージした結果、マージ後に状態行だけを更新する事務PR（#3）が必要になった。guardrailsが「mainへの直接push」を禁止しているため、この事務作業も毎回PRを要し、承認1回につきPRが2本になる。

## 決定

PRで提案する規程・A層のADRは、状態行を最初から「承認済み（本PRのマージをもって承認、日付）」と記載してよい。

- マージ前の読者にはPRの文脈で提案中であることが明白
- 却下時はPRごと閉じられADRはmainに入らないため、不整合な「承認済み」記述が本流に残ることはない
- チャット等PR外で人間が承認した判断のADR（ADR-0003のケース）は従来通り、承認の事実と日付を記載する

## 検討した代替案

- 案A: 事務PRを毎回出す（従来） / 不採用の理由: 情報量ゼロのPRが承認ごとに1本増える。人間のマージ操作も倍になる
- 案B: 状態更新に限りmainへの直接pushを許可する / 不採用の理由: guardrailsの例外は事故の入口。ルールの例外より記述の工夫で解決できる

## 帰結

- 承認1回=PR1本になる。本ADR自身がこの運用の最初の適用例
- meta/templates/adr.mdの運用ルールコメントに1行追記する
