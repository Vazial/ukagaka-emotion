# ADR-0069: テンプレの変更は、派生リポジトリ側が週に1回取りに行ってPRにする

> **承認者向けサマリ**
>
> テンプレから分かれたリポジトリが3本ある。テンプレの変更を届けるには、これまで毎回人が取り込みの道具を走らせ、
> 衝突を解き、PRを書いていた。2026-09-27 に3本へ手で届けたとき、道具が2種類あり、手順も衝突の出方もばらばらだった。
>
> 決定は4点。
>
> 1. 派生リポジトリ側が、週に1回テンプレを取りに行き、変更があればPRにする。サーバーのOrcaの自動実行で回す
> 2. 入口を1本のスクリプト（`meta/template-sync.sh`）にそろえる。手でも同じものを走らせられる
> 3. 衝突は「両側が同じファイルの末尾に追記しただけ」のときだけAIが解く。それ以外は止まってLinearにチケットを立てる
> 4. マージは人間が行う
>
> 払うもの: テンプレの変更が届くまで最大で約1週間かかる。急ぐときは手で走らせる。

## 文脈

テンプレ（`Vazial/ai-driven-dev-template`）から分かれたリポジトリは3本ある。

- dining-radar: 履歴ごと切り出した製品。共有ファイルの写しと、写した元の記録（`TEMPLATE_SYNC`）を持つ（ADR-0067）
- world-parameter-games・supplement-stack: テンプレをコピーして起こしたもの。テンプレ部分だけを積んだ枝を git merge して取り込む

2026-09-27、Linear と Orca で回す決まり（ADR-0068）を3本へ手で届けた。
道具が2種類あるため、呼び方も衝突の出方も違った。world-parameter-games では摩擦の台帳の末尾で衝突した。
supplement-stack では取り込みの基点がまだ宣言されておらず、台帳の番号もぶつかった。
gh（GitHub の CLI）が PR の宛先を `upstream`（テンプレ）と取り違え、PR をテンプレ側に出しかけた。

人間は「機械的に反映できるように整備したい」と依頼した。
届け方を3案出したところ、サーバーの Orca が週1で取り込む案を選び、手でも走らせられることを条件にした。

## 決定

### 1. 派生リポジトリ側が週に1回取りに行く

サーバーの Orca に、派生リポジトリごとに週1回の自動実行を登録する。
事前の判定（precheck）で取り込む変更があるかを見て、無ければ何もせずに終える。
取り込みの PR が開いている間は、次の取り込みを始めない。

テンプレ側から配る方式は採らない。非公開のリポジトリを書き換えられる鍵を公開のテンプレに預けることになるためである。

### 2. 入口を `meta/template-sync.sh` にそろえる

- `status`: 取り込む変更があれば終了コード 0、無ければ 1。受け取る範囲に変更が無ければ、テンプレが動いていても「無い」とする
- `pull`: ブランチを切り、各リポジトリの取り込みの道具を呼び、衝突が無ければ検証して PR まで出す
- `finish`: 衝突を解いたあとに走らせる。検証して PR を出す

スクリプトはテンプレの `meta/` に置き、写しとして派生リポジトリへ届く。取り込みそのものは各リポジトリの道具に任せる。
PR の宛先は、gh の既定ではなく `origin` の URL から決める。
`TEMPLATE_SYNC_DRY_RUN=1` を付けると push と PR 作成をせず、本文を表示するだけにする。

### 3. AIが解いてよい衝突は、末尾への追記同士だけ

摩擦の台帳のような追記専用のファイルで、両側が末尾に足しただけの衝突は、両方を残して解く。
順番はテンプレ側を先、そのリポジトリ固有の節を後にする。
それ以外の衝突と、検証が赤いときは、解かずに Linear にチケットを立てて止まる。

### 4. マージは人間が行う

PR 本文の「判断してほしいこと」には、衝突が無ければ「判断なし」、AIが解いたなら解いたファイルを書く。
人間は解き方が妥当かを見てマージする。

## 検討した代替案

- テンプレにマージしたら GitHub の自動処理が派生側へ PR を出す / 不採用の理由: 非公開リポジトリを書き換えられる鍵を公開リポジトリに預ける。衝突は解けずに止まる
- 派生側の GitHub が毎朝取りに行く / 不採用の理由: 非公開リポジトリの実行時間を使う（2026-09-27 に上限に当たった）。その仕組みで出した PR では CI が自動で走らない
- 2種類の取り込みの道具を1つに統一する / 不採用の理由: 写し方式と枝を積む方式は、切り出しか複製かという成り立ちの違いから来ている。入口をそろえれば足りる

## 帰結

- 取り込みは週1回の PR として届き、人はマージするかどうかだけを決めればよい
- 試し運転で、2026-09-27 に手で行った dining-radar と world-parameter-games の取り込みを再現し、中身が一致することを確かめた
- `meta/template-sync.sh` がまだ届いていない派生リポジトリでは、最初の1回だけテンプレの写しから手で走らせる
- 新しい派生リポジトリは、どちらかの取り込みの道具を持てばこの仕組みに乗る
