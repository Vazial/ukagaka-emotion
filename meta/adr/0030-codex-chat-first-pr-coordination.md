# ADR-0030: CodexはPR作成前にチャットでスコープを合意する

> **承認者向けサマリ**: Codexが、考えるための材料までPRへ載せてレビュー負荷を増やした。Codexは
> 新しいスライス・判断・PRの置き換えに着手する前に、目的、選択肢、PR範囲、検証方法をチャットで短く
> 合意する。PRは合意済み内容の差分とCI結果を確認する場とする。この規約はClaudeの運用を変えない。

## 文脈

Toyama Weekend Radarの開始時、Codexはプロジェクト統合ブランチの作成後に、既存PRの扱いと初回PRへ
含める内容をチャットで確認せずにPRを作成した。人間から、すべての検討をPRで読むことはレビュー負荷が
高く、ある程度の方向性はチャットで先に合意したいと指摘された。

Claudeはこの進め方で問題なく並行開発できているため、共有の規程やClaudeの入口規約を変える必要はない。
Codexだけに、PRを「決定を初めて提示する場」にしないための実行時ガイドラインが必要である。

## 決定

Codexは、新しいスライス、PRの置き換え、または判断を伴う変更の前に、次をチャットで提示して利用者の
スコープ確認を得る。

1. 目的と対象範囲・対象外
2. 判断が必要な場合の選択肢と採用案
3. ブランチ、PR範囲、検証方法
4. 既存PRまたはClaudeを含む他runtimeの未マージ作業への影響

確認後、Codexは合意済みスコープの実装・検証をPRへ載せる。実装中に新しい判断、矛盾、または実質的な
スコープ拡大が生じた時は、PRを作成・変更する前にチャットへ戻る。

チャット上の合意はPRの準備とレビューを進める許可であり、ADR・契約・規程などの正式な人間承認とは
区別する。合意済みスコープを変えない機械的なフォローアップ（CI完了の報告など）には新しい確認を要しない。

## 検討した代替案

- 案A: PRだけで全ての検討と承認を行う / 不採用の理由: 検討中の選択肢まで差分として読むことになり、
  PRレビューの負荷が高くなる。
- 案B: ClaudeとCodexの共有規程へ同じルールを追加する / 不採用の理由: Claudeは現状この問題を起こして
  おらず、実測のない共有規程変更は避ける。
- 案C: Codex専用の入口規約にチャット合意を追加する / 採用の理由: 観測されたCodexの問題だけを最小の
  実行時ガイドラインで防ぎ、PRを合意済み内容のレビューへ戻せる。

## 帰結

- `AGENTS.md` にCodex専用のchat-first coordination節を追加する。
- PR本文には、チャットで合意済みのスコープと検証結果を簡潔に記録する。
- 同種の摩擦が続く場合は、friction-logに記録し、より機械的な支援が必要かを再評価する。
