# ADR-0010: 監査レポートの冒頭に「承認者向けサマリ」を必須化する

## 文脈

RSV-Kの監査レポート（再監査記録込み約200行）に対し、人間から「読める分量ではない」「対訳表はもっと平易に」との指摘（FR-008）。orchestratorがチャットで平易版対訳表（1行1step・業務の言葉のみ）を作り直したところ好評だった。監査の証跡としての網羅性と、承認者が読む要約が同じ文書で兼用されていたことが原因。契約の可読性friction（FR-002/003→ADR-0002雛形）と同型の問題が監査レポートで再発した形。

## 決定

meta/templates/audit-report.mdを改訂し、冒頭に「承認者向けサマリ」節を必須化する:
- 結論1行（承認材料が揃った/差し戻し）
- 平易版対訳表: 1行1step、業務の言葉のみ。メソッド名・ファイル名・専門用語を使わない
- 要確認注記（あれば）のみ

詳細な監査証跡（技術的な対訳表・チェックリスト・機械突き合わせ結果）は後続の節に分離し、承認者は原則サマリだけ読めば承認判断できる構造にする。

## 検討した代替案

- 案A: reviewerへの指示で「平易に書く」ことを求める / 不採用の理由: 平易さは指示では安定しない。雛形の構造で強制する（FR-002/003で実証済みのアプローチ）
- 案B: orchestratorが毎回チャットで平易版を作る（今回の応急対応の恒常化） / 不採用の理由: 言い換えは劣化点（FR-006の教訓）。reviewer自身がコードから直接平易に書く方が正確

## 帰結

- 監査レポート雛形が「サマリ（承認者向け）+証跡（監査の記録）」の2部構成になる
- 人間の承認時間がさらに圧縮される（読む対象がサマリ節に限定）
