# ADR-0037: CodexはCLIを利用不能と報告する前にホスト側でも実体を確認する

> **承認者向けサマリ**: Codexが通常サンドボックス内のPowerShellで `gh` を発見できなかったことを、
> ホスト環境にもGitHub CLIが存在しないことと誤認した。以後CodexはCLIを利用不能と報告する前に、必要な
> 権限昇格を伴うコマンドプロンプトでの探索、または既知の実体パスへの読み取り専用確認を行う。CLIの発見、
> 認証状態、操作権限は別々に判定し、認証情報は出力しない。この手順をCodexが読む `AGENTS.md` に反映する。

## 文脈

CodexがGitHub操作に必要な `gh` を通常サンドボックス内のPowerShellから探索したところ、実行可能ファイルを
発見できなかった。Codexはその結果だけでホスト環境にも `gh` が存在しないと判断し、利用不能と報告した。
しかし、ホスト側から確認するとCLIは利用可能だった。限定された実行環境のPATHと、ホストにインストールされた
実体の有無を同一視したことによる誤判定である。

この誤判定は、利用可能な既存手段を使わずに作業を止め、人間へ不要な対応を求める。反対に、CLIを探すために
認証設定や環境変数を無差別に出力すると、認証情報を漏らす危険がある。また、実体の発見は、認証済みであることや
外部状態を変更してよいことを意味しない。実体の発見、認証、操作権限を分離した確認手順が必要である。

## 決定

1. Codexは、必要なCLIを通常サンドボックス内のシェルで発見できなかっただけでは「利用不能」と報告しない。
2. 利用不能と報告する前に、次のうち利用可能な経路でホスト側の実体を確認する。
   - 必要な権限昇格を明示して、コマンドプロンプトなど通常サンドボックスと異なるホスト側の探索経路から確認する。
   - 環境設定、過去の成功記録、またはツール出力から実体パスが既知なら、その絶対パスを直接確認する。
3. 発見確認は、実行ファイルの所在確認または `--version` 相当の読み取り専用操作に限定する。ホスト全体の無差別な
   再帰探索は行わず、通常の探索経路と既知の実体パスで確認できない場合に初めて利用不能として報告する。
4. CLIの**実体の有無**、**認証状態**、**対象操作に必要な権限・network到達性**を別々に判定する。ある層の失敗を
   別の層の不存在として報告せず、どの層で止まったかを明示する。
5. 発見・認証確認ではtoken、credential store、認証設定ファイルの内容、秘密を含み得る環境変数を出力しない。
   `gh auth token` のように秘密そのものを表示する操作は行わない。認証確認が必要な場合も、利用者へは秘密を含まない
   成否と次の対応だけを報告する。
6. CLIが見つかったことは、login、install、push、PR操作、ruleset変更などの外部変更を許可しない。実操作は
   `meta/permissions.md`、`meta/guardrails.md`、およびADR-0030のchat-first coordinationに従い、必要な承認を
   操作ごとに満たす。
7. このCodex固有の確認手順を `AGENTS.md` に反映する。今回の誤判定はfriction logへ記録し、同種の再発を
   追跡できるcause keyを持たせる。本ADRのarchitect成果物は決定の起草だけとし、`AGENTS.md` とfriction logの
   変更は同じスライスの別成果物として扱う。

## 検討した代替案

- **案A: 通常サンドボックスのPATHだけを正とする** / 不採用の理由: 今回、ホストに存在するCLIを不存在と
  誤判定した実績があり、実行環境の可視範囲をホスト全体の事実として扱えない。
- **案B: 発見できなければ直ちに利用者へ所在確認またはインストールを依頼する** / 不採用の理由: Codexが
  安全に実行できる追加確認を行わず、人間へ不要な作業と判断を戻す。
- **案C: ホストの全ディスクを再帰探索する** / 不採用の理由: CLI確認に対して探索範囲と実行時間が過大で、
  不要なファイル名や配置を露出させる。ホスト側の標準探索経路と既知パスで十分である。
- **案D: GitHub操作を常にブラウザまたはconnectorへ切り替える** / 不採用の理由: `gh` が利用可能な環境でも
  別経路へ固定し、既存の自動化と権限制御を活かせない。代替経路の利用可否も別途変動する。
- **案E: `AGENTS.md` に手順だけ追記し、ADRを残さない** / 不採用の理由: 人間裁定を運用文だけに埋めると、
  なぜホスト確認と秘密非出力が必要かという判断の履歴が失われる。

## 帰結

- Codexは、サンドボックスから見えないだけのCLIを「未導入」と誤報しにくくなる。
- CLIが実際に無い場合は追加の読み取り専用確認が1段増える。このコストを、不要な中断とインストール依頼を
  避けるための境界確認として受け入れる。
- 権限昇格はホスト側の発見確認に必要な最小範囲で使い、外部変更の権限とは分離される。
- 認証情報を出力せずに、実体・認証・権限・networkのどこで止まったかを報告できる。
- `AGENTS.md` への反映とfriction logへの記録が、この決定を現在のCodex運用と再発追跡へ接続する。
