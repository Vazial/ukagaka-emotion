# ADR-0070: 派生リポジトリは表に載せ、表と実際の登録の突き合わせを週1で機械に行わせる

> **承認者向けサマリ**
>
> 週1でテンプレを取り込む自動実行（ADR-0069）は、Orca にリポジトリごとに1件ずつ登録して動く。
> 派生リポジトリが増えても自動では増えない。登録を忘れたリポジトリは、テンプレの更新を受け取らないまま黙って古くなる。
>
> 決定は3点。
>
> 1. 派生リポジトリを `meta/derived-repos.md` の表に載せる。取り込みの自動実行を持つべきかどうかは、この表だけが決める
> 2. 表・Orca の自動実行・GitHub 上のリポジトリを突き合わせるスクリプト（`meta/derived-repos-check.sh`）を置く。読むだけで何も変えない
> 3. テンプレ側に週1の自動実行を1件足し、ずれがあれば直す。直せないものは Linear にチケットを立てる
>
> 払うもの: 表に1行足す作業は残る。ただし忘れる場所は「派生リポジトリを作る手順」の1か所に絞られ、書き忘れは GitHub との突き合わせで拾える。

## 文脈

2026-09-27、3つの派生リポジトリに週1の取り込みを登録した（ADR-0069）。人間から「新しい派生リポジトリが増えたときに登録を忘れないようにしたい」と出た。
手順書に4点を書く案（PR #211）をまず入れたが、読まれなければ防げない。人間の提案は「派生先の表を置き、各自それを見て反映する」形だった。

試しに GitHub 上の非公開リポジトリを調べると、`ai-driven-dev-template-private` がテンプレと同じ構造（HANDOFF.md・meta/PRINCIPLES.md）を持ちながら、
取り込みの道具も自動実行もなかった。2026-07-18 で更新が止まった、テンプレ本体の古い版に見える。表と突き合わせれば、こうしたものが最初に見つかる。

## 決定

### 1. 派生リポジトリは `meta/derived-repos.md` の表に載せる

列は、リポジトリ・方式・状態・備考。状態は「稼働」「対象外」「閉鎖」のどれか。
「稼働」なら週1の取り込みの自動実行が要る。「対象外」「閉鎖」なら要らず、あれば外す。

### 2. 突き合わせは `meta/derived-repos-check.sh` が行う

次の3種類のずれを1行ずつ出す。読むだけで何も変えない。

- 追加: 表で「稼働」なのに、自動実行が無い
- 外す: 表で「対象外」「閉鎖」なのに、自動実行が残っている
- 表に無い: GitHub 上にテンプレの構造（HANDOFF.md）を持つのに、表に載っていない

ずれがあれば終了コード 0、無ければ 1（Orca の事前判定にそのまま使える）。

### 3. 週1の自動実行をテンプレ側に1件置く

事前判定でずれがあるときだけ動き、次のとおり直す。

- 追加: リポジトリが取り込みの道具を持っていれば登録する。持っていなければ登録せず、初回の取り込みが要ると Linear に書く
- 外す: 自動実行を外す
- 表に無い: 表に足すか、対象外にするかは人間が決める。Linear にチケットを立てる

## 検討した代替案

- 手順書に4点を書くだけにする / 不採用の理由: 読まれなければ防げない。手順書は残すが、それだけには頼らない
- 表を持たず、GitHub 上のリポジトリを走査して自動実行を作る / 不採用の理由: テンプレ構造を持っても取り込む相手でないものがある（更新が止まった旧版など）。相手を決めるのは人間で、その記録が表になる
- 表を activeContext に置く / 不採用の理由: activeContext は「現在の状態」の置き場で、プロジェクトの一覧がある。リポジトリは別の粒度で、機械が読むので、専用の文書に分けた

## 帰結

- 派生リポジトリを作る手順の末尾が「表に1行足す」になり、あとは週1の突き合わせが見張る
- 突き合わせのスクリプトは、表を書き換えた版で「追加」「外す」が出ること、対象外に直すと「表に無い」が消えることを確かめた
- 最初の実行で `ai-driven-dev-template-private` が「表に無い」と出る。表に足すか対象外にするかは、この ADR とは別に人間が決める
- Orca に登録できるのはこのマシンに複製済みのリポジトリだけである。新しい派生リポジトリは、先に Orca に追加しておく
