# ADR-0060: セッション中の会話も、読む人が読み切れる量に収める

> **承認者向けサマリ**
>
> AIが人間に判断を仰ぐとき、質問の前に長い調査報告を貼り、そのうえで答えようのない問いを
> 並べていた。人間は3つの質問のどれにも答えられず、「何を言ってるかまったくわからない」
> 「すごくイライラする」と指摘した。
>
> 調べたところ、3つの質問はいずれも、このリポジトリが既に決めているルールに反していた。
> 足りなかったのはルールではない。ルールの向き先である。承認する文書の冒頭、ADRの本文、
> PRの本文には、それぞれ読みやすさのルールがある。会話そのものには何も無い。そして人間が
> 読む量の大半は会話である。
>
> 決定は6点。
>
> 1. 会話に出すのは結論と判断と次の一手だけにする。調査の経過はファイルに置いてリンクを渡す
> 2. 判断を仰ぐときは選択ボタンで出す。地の文で「どうしますか」と書かない
> 3. 選択肢の文面に、このリポジトリを知らない人に通じない語を入れない
> 4. 「わからない」と返ってきたら、説明を足さずに言葉を替えて出し直す
> 5. 言い直しの非常ボタンとして `/eli5` を置く
> 6. 機械検査は足さない。ただし後退条件を先に書いておく
>
> 払うもの: 会話が短くなる分、証跡はファイルへ移る。すぐ目に入らない情報が増える。

## 文脈

### 1. 何が起きたか

2026-08-23、人間から指摘が出た。「Claudeが許可を求めてくるけど何を言ってるかまったく
わからない」「どうにかしてほしい、すごくイライラする」。証拠として、別のセッションでAIが
実際に出した文面が貼られた。

その文面は、およそ2000字の調査報告のあとに質問を3つ並べたものだった。人間の反応は質問ごとに
「意味が分からない」「メリデメもわからない」「認知負荷が高すぎて答えられない」「何を言ってるの？」
である。3問とも答えられていない。判断は1つも進まなかった。

### 2. 3つの質問を、既存のルールに当てて測った

| 出した質問 | 何が欠けていたか | どのルールに反するか |
|---|---|---|
| 「ADRの番号をどこへ振り直しますか」 | 選択肢が無い。自由記述で聞いている | 判断を仰ぐときは選択肢とトレードオフを揃えて出す（ADR-0051 決定1） |
| 「上流の決定を取り込みますか」 | 選択肢が「取り込む（推奨）」の1つだけ | 選択肢が1つなら判断依頼ではなく報告である（ADR-0051 決定2） |
| 「上流との同期を今後どう繰り返しますか」 | 選択肢が無い。しかも運用手順の起案はAIの領分 | 同上。AIが自分で決めてよいことは聞かない（ADR-0051 決定2） |
| 質問の前のおよそ2000字 | ファイル名・ADR番号・このリポジトリでしか通じない語が説明なしで並ぶ | 人間が承認する材料は平易な言葉で書き、実装詳細を混ぜない（ADR-0016） |

3問すべてが、成文化済みのルールに反している。ルールが無かったのではない。

### 3. なぜルールがあるのに治らないのか

原因は3つに分かれる。

第一に、ルールの向き先が文書の一部に限られている。承認する文書の冒頭を平易にする決定
（ADR-0016）、ADR本文を単独で読めるようにする決定（ADR-0053）、PR本文を初見の人向けに書く
決定（ADR-0057）。どれも書き上がった成果物を対象にしている。会話そのものを対象にした規程は
無い。人間が実際に読む量の大半は会話である。一番広い面が規程の外にあった。

第二に、会話は成果物に残らないため機械で数えられない。判断依頼の型を決めた議論（ADR-0051）は
この理由で機械検査を見送った。守らなくても何も起きない状態が続いている。

第三に、調べた直後の書き手には、調べた内容がすべて既知になっている。何が読み手にとって未知かの
感覚が失われる。そこへ、調べた量を示したい動機が重なる。あの2000字は説明ではなく作業量の提示
だった。人間が判断するのに要ったのは、そのうち3行である。

第一と第二は構造の問題、第三は書き手の癖である。本ADRは第一を埋め、第三には出し直しの手段を
用意する。第二は変えない（決定6）。

### 4. これは同じ原因の再発である

読み手の前提知識を当てにして書いてしまう摩擦は、A層の台帳の FR-001（承認済みのADRが1枚だけ
読んで分からないと指摘された件）と同じ原因に当たる。一般則を作った ADR-0016 より後に数えて、
これで5回目になる。

ADR-0051 は末尾に「再発したら、それは空白の問題ではなかったという情報だ」と書き残していた。
今回は再発だが、面が違う。会話には初めから規程が無かった。空白はまだ残っていた。

## 決定

### 決定1. 会話に出すのは、結論と判断と次の一手だけにする

調査の経過・件数・ファイルの一覧・差分の分類は、会話の本文に貼らない。ファイルかPR本文に
置き、会話にはリンクだけを渡す。読むかどうかを人間が選べる形にする。

判断を仰ぐ前に置く前置きは10行を目安とし、超えるならファイルへ移す。

### 決定2. 判断を仰ぐときは選択ボタンで出す。地の文で問わない

Claude Code には選択肢を提示する専用の道具がある（`AskUserQuestion`）。この道具を使うと、
短い質問文・2〜4個の選択肢・選択肢ごとの説明が、道具の側から必須になる。ADR-0051 決定1が
求める4点のうち3点が、心がけではなく仕組みで強制される。

地の文に「どうしますか」と書いて判断を仰ぐことを禁じる。一度に出す質問は2問までとする。

### 決定3. 選択肢の文面に、外の人に通じない語を入れない

入れないもの: ADR番号・FR番号・信条の番号・ファイルパス・このリポジトリでしか通じない語。

選択肢の説明には、それを選ぶと何が起きるかを書く。得るものと失うものが1行で分かるようにする。
これは ADR-0016 が承認文書の冒頭に課した平易さを、選択肢の文面まで広げたものである。

### 決定4. 「わからない」と返ってきたら、説明を足さずに言葉を替えて出し直す

「わからない」は、選択肢の文面が失敗した合図として扱う。説明を足すと読む量が増えるだけで、
負荷はかえって上がる。用語を捨てて、選び直せる形にして出し直す。

出し直しても通らなければ、推奨案で仮決めして作業を進める。決めた内容と、覆したいときにどこを
見ればよいかを記録に残す。人間を待たせて止まらない。

### 決定5. 言い直しの非常ボタンとして `/eli5` を置く

決定1から4をすり抜けたときのために、直前の説明を中学生に通じる言葉で言い直させる道具を置く。
会話にもPR本文にもADRにも使える。`.claude/skills/eli5/` に置く。

これは予防ではなく救済である。呼ばれた回数そのものが、決定1から4が効いていない目安になる。

### 決定6. 機械検査は足さない。後退条件を先に書く

会話は成果物に残らないため、書かれた量も語彙も後から数えられない。ADR-0051 決定4と同じ判断で
ある。

後退条件を先に書いておく。本ADR以降も同じ指摘が出たら、原因は書き手の癖ではなく仕組みの不足と
みなす。そのときは会話の側ではなく道具の側で縛る。地の文での判断依頼をフックで止める案を、
最初の候補として検討する。

## 検討した代替案

- 案A: `/eli5` だけ置き、規程は変えない / 不採用: 読んで疲れたあとにしか効かない。疲れること
  自体を防げない。人間の要求は「読む前から分かる状態」である
- 案B: 会話の分量や語彙を機械で数える / 不採用: 会話は成果物に残らず、後から読み取る手段が無い
- 案C: 信条（`PRINCIPLES.md`）に新しい項として足す / 不採用: ADR-0016 と ADR-0051 が同じ理由で
  退けている。本件は「人間の関与を意図の表明と重要判断に集中させる」という信条（P-01）の運用
  規約であって、独立した公理ではない
- 案D: 役割定義（`.claude/agents/`）にも同じ文を書く / 不採用: `meta/permissions.md` は冒頭で
  全agentを対象と宣言しており、役割定義への複製は必ずずれていく。ADR-0051 の案Dと同じ理由
- 案E（採用）: `meta/permissions.md` の判断依頼の節に追記し、`/eli5` を救済として足す

## 帰結

- `meta/permissions.md` の「人間に判断を仰ぐときの型」に決定1から4を追記する。既存の4点は
  変えない。追加であって書き換えではない（P-06）
- `.claude/skills/eli5/` を新設する。このリポジトリで最初のスキルになる
- A層の台帳に摩擦を1件追記する。原因のキーは FR-001 と同じものを使う
- 会話が短くなる分、証跡はファイルへ移る。リンクの置き方が悪いと、今度は「どこに書いてあるか
  分からない」という別の摩擦になる。次に測るのはそこである
- 選択ボタンは Claude Code の道具であり、Codex に同じものがあるとは限らない。Codex 側では
  決定1・決定3・決定4だけが効く。決定2は運用で代替する
