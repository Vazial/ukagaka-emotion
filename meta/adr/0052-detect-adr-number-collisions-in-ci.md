# ADR-0052: ADR採番の衝突をCIで検出する。確認範囲を「オープンPR」から「未マージの全ブランチ」へ広げる

> **承認者向けサマリ**: ADRの通し番号の衝突が**4回**起きている（`FR-023`・`activeContext`）。
> `meta/adr/0026` 決定4 は既に「mainだけでなくオープン中のPRも確認してから番号を取る」と定めて
> いるが、**2回目は規程を守らずに起き、4回目は規程を守っても防げなかった**——相手が
> **PRを持たないリモートブランチ**（`meta/designer-adopts-design-skill` が `0050` を保持）だった
> ためである。同ADR 決定4 手順4 は「CIで機械強制できない」と結論していたが、その根拠は
> **govlintがワーキングツリーしか見ない**ことであり、**GitHub APIを使う別ジョブなら他の未マージPRの
> 差分を読める**。決定は4点。**(1)** 採番前の確認範囲を「オープンPR」から**未マージのリモート
> ブランチ全部**へ広げ、確認コマンドを `meta/guardrails.md` に具体で置く。**(2)** CIジョブ
> `.github/workflows/adr-number.yml` を新設し、**ツリー内の重複**と**他のオープンPRとの衝突**を
> 検出して落とす。落ちるのは後発のPR＝**振り直すべき側**である。**(3)** PRを開いていないブランチは
> CIから原理的に見えないため、`0026` 決定4 手順2（番号を取ったら即Draft PR化）を**この検査が成立する
> 前提条件**として格上げする。**(4)** required check にはしない（rulesetはgit管理外の人間の操作。
> 赤が見えれば足りる、で始める）。

## 文脈

### 0. このADRの起草者について（meta/adr/0047）

本ADRは orchestrator が起草した。素材は採番衝突という摩擦の観測であり、`0047` 決定2 の目安に当たる。

### 1. 4回の衝突と、そのたびに何が効かなかったか

| 回 | 何が起きたか | 既存の防御が効かなかった理由 |
|---|---|---|
| 1（`0037`） | Codexとの同時起票 | 規程を守っても防げない競合。事後に振り直して解消 |
| 2（`0044`） | `0026` を守らずmainだけ見て採番 | **自己申告の限界**。手順はあったが実行されなかった |
| 3（`0048`） | `meta/designer-adopts-design-skill` の `0048` がmainの `0048` とぶつかる | govlintが昇格前に検出（mainに載っていたため） |
| 4（`0050`→`0051`、本件の直前） | 3回目の振り直し先 `0050` を、別セッションがさらに取った | **衝突する2本がどちらも未マージ**。govlintは各ブランチ単体では緑を返す。しかも相手は**PRを持たないブランチ**だったため、`0026` 決定4 手順1（オープンPRを確認）を守っても見つからない |

つまり残っている穴は2つである。**(a) 確認範囲が「オープンPR」止まりで、PRの無いブランチを覆っていない**。
**(b) 確認が自己申告であり、2回目のように実行されなければ何も起きない**。

### 2. 「機械強制できない」は govlint についてだけ正しい

`0026` 決定4 手順4 はこう書いている——「オープンPR間の採番衝突はgovlintの検証範囲外である……govlintは
1PRのワーキングツリーしか見ず、他の未マージブランチの内容を知りようがない」。

これは `meta/tools/govlint.py` については**正確**である（`ROOT` 配下の実ファイルのみを走査し、
ネットワークを使わない。この性格は `0014` 以来の設計であり、壊す理由がない）。

しかし**CIジョブ一般**については正しくない。GitHub Actions は `GITHUB_TOKEN` を持っており、
`gh api repos/:o/:r/pulls/:n/files` で**他のオープンPRが追加したファイル名**を読める。採番の衝突判定に
必要な情報はファイル名だけである——中身の意味を読む必要がない。**判定できる対象を、判定できる道具で
判定していなかった**というのが本件の実態である。

### 3. どの案を採ったか

人間へ4案を提示し（`meta/adr/0051` §2 の型）、**案2（CI検出）＋案1（規程の範囲を広げる）**が選ばれた。

- **案3（起票前に叩くローカル採番ヘルパー）**は却下。衝突する前に効く唯一の案だが、**叩くかどうかが
  人任せ**という点で案1と同じ弱点を持ち、かつ置き場が施錠下の `meta/tools/**` しかない現状では人間の
  開錠コミットを要する（`0046`）
- **案4（番号制の廃止。slug主体・日付ID）**は却下。衝突は構造的に消えるが、本文中の相互参照
  （`meta/adr/0039` のような表記）が全ADRに散在しており、govlintのADRリンク検査も作り直しになる。
  P-06（承認済みADRは編集しない）と噛み合わない大移動になる

## 決定

### 決定1. 採番前の確認範囲を「未マージのリモートブランチ全部」へ広げる

`0026` 決定4 手順1 は「オープン中の全PR」を確認範囲としていた。**PRを持たないブランチ**が番号を握って
いた4回目の実例により、この範囲では足りないことが判明した。範囲を**未マージのリモートブランチ全部**へ
広げ、`meta/guardrails.md` §2 に確認コマンドを具体で置く。

```bash
git fetch --all --quiet
for b in $(git ls-remote --heads origin | awk '{sub("refs/heads/","",$2); print $2}'); do
  git ls-tree -r --name-only "origin/$b" -- meta/adr | grep -oE '[0-9]{4}'
done | sort -u | tail -5
```

`0026` 決定4 手順1〜3 は**変更しない**（P-06）。本決定が改めるのは手順1の**範囲**だけである。

### 決定2. CIジョブでADR採番の衝突を検出する

`.github/workflows/adr-number.yml` を新設する。`pull_request`（base=`main` または `project/**`）で走り、
2つを検査して、どちらかに当たれば失敗する。

1. **ツリー内の重複**: チェックアウトしたツリーに、同じディレクトリ・同じ番号のADRが2つ以上ある
   （＝main上に既にある番号を取った場合。3回目の形）
2. **他のオープンPRとの衝突**: このPRが**追加または改名**したADR番号を、他のオープンPRが同じ
   ディレクトリで主張している（＝4回目の形のうち、相手がPRを持っている場合）

**落ちるのは後発のPR**である——先に開いたPRは自分のCIをもう走らせ終えており、後から開いた側が相手を
見つけて赤くなる。振り直すべきは後発の側なので、この非対称性は都合が良い。

判定対象は `meta/adr/` に限らず `projects/<p>/adr/` も同じロジックで見る（ディレクトリごとの名前空間。
`0026` が「プロジェクトADRは別名前空間ゆえ衝突しない」と述べたのは**プロジェクト間**の話であり、
**同一プロジェクトの2ブランチ間**では同じ衝突が起こりうる）。

**govlintに足さない理由**は2つ。(a) govlintは「ネットワーク不使用・ROOT配下のみ」という性格を保って
おり（`0014`）、他PRの差分取得はその性格を壊す。(b) `meta/tools/**` は施錠されており（`0046`）変更に
人間の開錠を要するが、**採番の突き合わせは「何を正しいと判定するか」を左右しない**——番号がぶつかって
いるかどうかは意味判定を含まない事実であり、この検査を弱めても不正な成果物は通らない。施錠の手続に
載せる理由がない。

### 決定3. 「番号を取ったら即PR化」を、検査が成立する前提条件として格上げする

GitHub Actions は**対象PRのイベントでしか走らない**。したがってPRを開いていないブランチが握る番号は、
決定2の検査からも**原理的に見えない**（4回目の相手がまさにそれだった）。

`0026` 決定4 手順2（番号を確保したら本文を書き終える前にプレースホルダをコミットし、Draft PRでよいので
直ちに開く）は、これまで「他人に見つけてもらうための親切」だったが、本ADR以降は**機械検出が働くための
前提条件**である。**PRを開かずに番号だけ握る行為は、検出網の外に出る行為である**と明記する。

### 決定4. required check にはしない

branch protection の必須チェック一覧の変更は、git管理外のGitHub設定を人間が操作する行為である
（`meta/guardrails.md`・`0026` 決定1.3）。現状は **L0（govlint）のみ hard-required** であり、本検査は
PR画面で赤が見える状態から始める。**required化が要ると分かった時点で人間が設定する**（P-05）。

## 検討した代替案

本ADRの選択肢そのものは文脈3のとおり人間が選んだ（案1＋案2採用、案3・案4却下）。実装上の代替案を
以下に残す。

- **案a: govlintに他PR照会を足す** / 不採用: 決定2の理由(a)(b)。とくにgovlintの「ネットワーク不使用」を
  壊すと、L0がGitHubの応答性に依存するようになる（共有の常時必須ゲートで避けたい性質である）
- **案b: 判定スクリプトを `.github/scripts/` に切り出して単体テストを付ける** / 不採用（現時点）:
  `0014` は「ロジックを持つ検証インフラはテスト付きでdeveloperが実装する」と定めており本来この形が
  正しい。ただし本検査のロジックは**ファイル名から4桁を拾って突き合わせるだけ**で、意味判定も閾値も
  持たない。ワークフローに直書きして1ファイルで読み切れる状態を優先する。**ロジックが増えるなら
  その時点で切り出してテストを付ける**（P-05）
- **案c: 番号の予約台帳（`meta/adr/README.md` 等）をmainに先出しする** / 不採用: 起草のたびに極小PRが
  1本増える。`0035` が「差分2行のPRは飛ばされる」と観測した構造と同型であり、飛ばされれば台帳は
  嘘になる。`0026` 決定4 手順2（プレースホルダPR）が既に同じ役目を、追加のPRなしで果たしている

## 帰結

- **塞がるもの**: 3回目の形（main上の番号との衝突）と、4回目の形のうち相手がPRを持つ場合。**自己申告
  ではなく機械が落とす**ため、2回目の形（規程を守らなかった）も塞がる
- **残る穴**: PRを持たないブランチが握る番号（決定3で運用に押し戻した）。および、先に開いたPRが後発の
  衝突に気づけないこと——ただし振り直すべきは後発なので実害は小さい
- **runtime非依存**: この検査はGitHub側で走るため、`.claude/settings.json` の deny や hook と違い
  **Codexのブランチにも等しく効く**（`activeContext` の留意事項「runtime横断で効かせたい規律は権限設定
  ではなく共有ゲートに置く」に沿う）
- **テストが無い**: 案bのとおり、ロジックをワークフローに直書きしたためgovlint本体のような単体テストが
  無い。**両方の経路（衝突なし／衝突あり）を起票時にローカルで実行して確認した**——`gh` の標準出力を
  locale任せで読むと非UTF-8環境で黙って空配列になる（＝「他のPRは1本も無い」と誤読する）ことを実測し、
  `encoding="utf-8"` を明示して潰してある
- **`FR-023` は追記しない**（friction-logは追記専用・既存FRは編集しない）。本ADRが4回目への回答である
  ことは `activeContext` の当該行から辿れる
